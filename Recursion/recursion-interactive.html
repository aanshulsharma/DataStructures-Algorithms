1. Recursion hota kya hai?

⏱ 5 min · basic samajh

Recursion matlab — ek function apna kaam karne ke liye khud ko hi call karta hai, lekin har baar thoda chhota problem deke. Ye tab tak chalta hai jab tak problem itna chhota na ho jaaye ki answer seedha pata ho.

Desi example — Railway ticket ki lambi line 🚉:
Tum line mein kahin peeche khade ho aur jaanna hai "Main kaunse number pe hoon?" Gin-ne ka mood nahi hai. Toh tum aage wale bhaiya se puchte ho: "Bhaiya, aap kaunse number pe ho?" Woh bhi nahi jaante, toh woh apne aage wale se puchte hain… ye sawaal aage badhta jaata hai.
Sabse aage wala banda counter pe khada hai — use pata hai "Main 1st hoon". Yahi hai base case (jahan answer seedha pata hai).
Ab jawaab wapas aata hai: har koi apne aage wale ka number + 1 bolta hai. Tumhe bhi apna number mil gaya! 🎉
🚉 Khud try karo: "Main line mein kaunse number pe hoon?"

Roz ki life mein recursion kahan dikhta hai?

🍱 Tiffin ke dabbe

Steel ke dabbe ka set — bade dabbe ke andar chhota dabba, uske andar aur chhota. Sabse chhota dabba khulta hi nahi = base case.

📁 Phone ka Gallery / WhatsApp folder

Folder ke andar photos aur folders. Saari photos ginni hain? Is folder ki photos + har sub-folder ko same tareeke se gino.

💈 Salon ke do sheeshe

Nai ki dukaan mein aamne-saamne do mirror — image ke andar image ke andar image… Ye kabhi rukta nahi, isliye code mein rukne ka rule chahiye.

👨‍👩‍👧 Family tree

"Dada ji ke kitne pote-potiyan?" = har bete ke bachche + unke bachche… har branch pe wahi sawaal.

🌳 Bargad ka ped

Badi shaakh se chhoti shaakhein nikalti hain, jo dikhti bilkul badi shaakh jaisi hain.

🪆 Russian gudiya

Gudiya ke andar gudiya. Sabse chhoti solid gudiya pe ruk jaate ho.
Ek line mein yaad rakho: Bada problem = (thoda sa apna kaam) + (wahi problem, lekin chhota).

2. Recursive function ke 3 zaroori masale

⏱ 5 min · recipe ke ingredients

Jaise chai mein paani, patti, doodh zaroori hai, waise hi har sahi recursive function mein ye 3 cheezein honi chahiye. Button dabao aur dekho code mein kahan hain:

static int factorial(int n) {
    if (n <= 1) return 1;                 // base case
    return n * factorial(n - 1);  // recursive case
}
Upar koi ek button dabao.
Factorial kya hai? 5! = 5 × 4 × 3 × 2 × 1 = 120. Socho shaadi mein 5 rishtedaar ek line mein photo ke liye kitne tareekon se khade ho sakte hain? 120 tareeke! 📸
Aur dekho: 5! = 5 × 4!, aur 4! = 4 × 3! … yani bada factorial = number × chhota factorial. Yahi recursion hai.

Poora Java code


  
Base case bhool gaye → function khud ko hamesha call karta rahega → StackOverflowError 💥.

  Progress bhool gaye (jaise factorial(n-1) ki jagah factorial(n) likh diya) → wahi tabaahi. Jaise ghar se nikle aur gol-gol ek hi gali mein ghoom rahe ho — kabhi pahunchoge nahi.

4. Recursive tareeke se sochna kaise?
⏱ 6 min · "bharosa rakho" wala trick
  
Shuru mein sab log har call ko dimaag mein trace karne ki koshish karte hain — sir dard ho jaata hai. 😵 Pro log "Leap of Faith" (bharosa) use karte hain: maan lo ki chhote input ke liye function already sahi kaam karta hai. Tumhe bas itna sochna hai ki us answer ko use kaise karna hai.

  
Desi example — Kirana ka bill 🧾: Papa ne bola "bill ka total batao". Tum pehli item ka price khud dekh lete ho, aur baaki bill chhote bhai ko de dete ho: "tu baaki ka total bata". Tumhe bhai pe bharosa hai. Bhai bhi yahi karta hai — pehli item khud, baaki aur chhote ko. Jab bill khaali, answer = 0. 😄

  

    
🧠 Kirana bill ka total — step by step solution banao

    

      
Step 1 — Kya chahiye? sum(bill) = bill ki saari items ka total.

      
Step 2 — Sabse chhota case (base). Khaali bill ka total = 0.

      
Step 3 — Bharosa (leap of faith). Maan lo sum(baaki bill) sahi answer deta hai. Use baaki bolo.

      
Step 4 — Jodo. sum(bill) = pehli item + baaki.

      
Step 5 — Progress check. Har call mein bill 1 item chhota hota hai, toh ek din khaali hoga hi. ✅

      

    

    

  

  
Recursion ki recipe (ratt lo 📝):
1️⃣ Sabse chhota input kya hai? → base case.
2️⃣ Input ko ek step chhota kaise karun? → recursive call.
3️⃣ Chhote ka answer mil gaya, ab bade ka kaise banaun? → combine.

  
Order matter karta hai: call se pehle vs. call ke baad

  
Socho tum seedhiyan utar ke basement jaate ho aur wapas aate ho. Jo kaam call se pehle likha hai woh neeche jaate waqt hota hai, aur jo call ke baad likha hai woh wapas upar aate waqt.


static void seedhi(int n) {
    if (n == 0) return;                          // basement aa gaya
    System.out.println("neeche ja raha " + n);   // call se PEHLE (jaate waqt)
    seedhi(n - 1);
    System.out.println("upar aa raha " + n);     // call ke BAAD (aate waqt)
}

  
Upar wale visualizer mein countdown chuno aur dekho — 3 2 1 jaate waqt print hota hai aur 1 2 3 aate waqt.







  
5. Tree recursion: Fibonacci aur "copy mein likh lo" trick
⏱ 10 min · ek se zyada calls + memoization
  
Jab function khud ko ek se zyada baar call karta hai, toh calls ek ped (tree) jaisa bana deti hain. fib(n) = fib(n-1) + fib(n-2).

  
Fibonacci kya hai? 0, 1, 1, 2, 3, 5, 8, 13… — har number pichhle do ka jod. (Fun fact: ye series pehle Indian scholars Pingala aur Hemachandra ne Sanskrit chhand/poetry ke patterns mein describe ki thi! 🇮🇳)

  

  

    
🌳 Fibonacci ka call tree

    

      
      
      
    

    

    

    

      ● normal call   ● base case (n ≤ 1)   ● answer copy mein mil gaya (cache). Kisi gol pe mouse le jao: same n wali saari calls chamkengi — yahi bekaar ki mehnat hai!

  

  
Desi example — Rishtedaaron ka sawaal 👵: Shaadi mein har rishtedaar puchta hai "Beta, aajkal kya kar rahe ho?" Agar tum har baar naye sire se soch ke jawaab do, toh thak jaoge. Smart tareeka: ek baar jawaab yaad kar lo, aur sabko wahi bol do. 😄

  
Memoization = jo answer ek baar nikal liya, use copy mein likh lo. Agli baar wahi sawaal aaye toh copy dekho, dobara solve mat karo. Isse O(2ⁿ) ka kaam O(n) mein ho jaata hai. Upar checkbox ON/OFF karke calls ki ginti compare karo.

NestedCall ke andar argument bhi ek recursive callSawaal ke andar sawaalAckermann function

  

  

    

      Tail recursive NAHI hai (call wapas aane ke baad multiply karna baaki hai)

static int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);   // wapas aake n se multiply
}

    

    

      Tail recursive HAI (answer acc mein saath le ke chal rahe ho, jaise gullak 🐷)

static int fact(int n, int acc) {
    if (n <= 1) return acc;
    return fact(n - 1, n * acc);   // bas call, aur kuch nahi
}
// aise call karo: fact(5, 1)

    

  

  
Dhyaan do: Kuch languages (jaise Scheme) tail call ko optimise kar deti hain taaki stack na badhe. Java aisa NAHI karta — toh Java mein tail recursion bhi bahut deep input pe StackOverflowError de sakta hai. Bahut bada input ho toh loop use karo.

  
Mutual recursion — Mummy-Papa wala scene

  
Bina base case ke ye kabhi khatam nahi hota ("Papa se pucho" ↔ "Mummy se pucho" 🔁). Isliye yahan n == 0 pe rukna zaroori hai:


static boolean isEven(int n) { return n == 0 ? true  : isOdd(n - 1); }
static boolean isOdd(int n)  { return n == 0 ? false : isEven(n - 1); }







  
7. Tower of Hanoi — Kashi ke mandir ki kahani
⏱ 10 min · pehle khelo, phir recursion samjho
  
Kahani 🛕: Ek purani kahani hai ki Kashi (Banaras) ke ek mandir mein pujari 64 sone ki thaaliyan ek khambe se doosre khambe pe shift kar rahe hain. Rule: ek baar mein ek thaali, aur badi thaali kabhi chhoti ke upar nahi. Kehte hain jab kaam poora hoga, duniya khatam ho jaayegi! (Chinta mat karo — 64 thaaliyon mein 2⁶⁴ − 1 moves lagenge, yani 1 move per second se ~58,000 crore saal 😄)

  
Tumhe thaaliyan khambe A se C pe le jaani hain. Kisi khambe pe click karo = upar wali thaali uthao, doosre pe click = wahan rakho.

  

    

      
      
      
    

    

    

    

  

  
Recursion wali soch: n thaaliyan A se C le jaani hain?

  1. Upar ki n-1 thaaliyan A → B rakh do (C ki madad se) — bharosa rakho ki ho jaayega!

  2. Sabse badi thaali A → C rakh do.

  3. Wo n-1 thaaliyan B → C rakh do (A ki madad se).

  Base case: 0 thaali → kuch mat karo. Kam se kam moves = 2ⁿ − 1.

  







  
8. Backtracking: Chai ke saath kya loge? (Subsets)
⏱ 8 min · "lena hai / nahi lena"
  
Shaam ki chai 🍵 ke saath tapri pe 3 cheezein hain: Samosa, Jalebi, Pakoda. Kitne alag-alag combos ban sakte hain? Har item ke liye do hi option: lo ya chhodo. Ek item decide karo, baaki items ke liye wahi sawaal (recursion!). Jab saare items decide ho gaye — ek combo ready.

  
S → lena/nahi (2) × J → lena/nahi (2) × P → lena/nahi (2) = 2³ = 8 combos (khaali plate bhi ek option hai — diet wala din 😅).

  

  
👉 Lesson 3 ke visualizer mein subsets chuno, input SJP daalo aur step-by-step dekho. Screen pe print hua box mein saare 8 combos aayenge.

  

    
🎛 Kitne items, kitne combos?

    

    

  

  
Backtracking = recursion + apna faisla wapas lena. Jaise kapde ki dukaan mein ek shirt try ki, nahi jami toh utaar di aur agli try ki. Sudoku, N-Queens, maze (bhool-bhulaiya) solve karna — sab isi se hota hai.

10. Common galtiyan & Recursion vs. Loop
⏱ 6 min · in gaddhon se bacho
  

    
❌ Base case hi nahi
static int sum(int n) { return n + sum(n - 1); }
Jaise auto wale bhaiya ko pata hi nahi kahan rukna hai. 🛺
Fix: if (n == 0) return 0;

    
❌ Problem chhota hi nahi hua
static int f(int n) {
    if (n == 0) return 0;
    return f(n);   // same n! 
}
Jaise roundabout pe gol-gol ghoomte rehna. 🔄
Fix: f(n - 1) call karo.

    
❌ Base case tak kabhi pahunche hi nahi
static void countdown(int n) {
    if (n == 0) return;
    countdown(n - 2);  // odd n pe 0 skip ho jaata hai
}
Jaise do-do seedhi kood ke chadh rahe ho aur jis seedhi pe rukna tha wahi skip ho gayi. 🪜
Fix: n <= 0 use karo.

    
❌ Same kaam baar-baar
Naive Fibonacci same values baar-baar nikaalta hai — jaise har rishtedaar ke liye naye sire se jawaab sochna. Fix: memoization / dynamic programming.

  

  
Recursion vs. Loop — kab kya?

  

    
RecursionLoop

    
Kahan best haiKaam ke andar wahi kaam — folder ke andar folder, family tree, tree/graph, backtrackingSeedha repeat wala kaam — 100 laddoo gin-na, 1 se 10 print karna

    
MemoryCall stack use karta hai (overflow ka risk)Extra memory lagbhag zero

    
Padhne meinSelf-similar problems mein bahut saafSeedhi line wale problems mein saaf

  

  
Thumb rule 👍: Problem ped ki tarah branch karta hai ya andar-andar nested hai → recursion. Seedhi line hai → loop.
