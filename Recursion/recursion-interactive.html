1. What is recursion?

⏱ 5 min · intuition

Recursion is when a function solves a problem by calling itself on a smaller version of the same problem, until the problem is so small that the answer is obvious.

Real-life picture: A set of Russian nesting dolls. To find the smallest doll, you open the current doll — and inside is another set of dolls (the same problem, but smaller). Keep going until a doll is solid. That solid doll is the base case.

Click Open next doll to start.

Other places you see recursion

📁 Folders

A folder contains files and folders. To count all files, count the folder's files + count each sub-folder the same way.

🪞 Two mirrors

A mirror reflecting a mirror reflecting a mirror… (with no end — which is why we need a stopping rule!)

🌿 Trees & Fractals

A branch splits into smaller branches that look like the whole tree.
Key idea: Big problem = (tiny piece of work) + (the same problem, but smaller).

2. Anatomy of a recursive function

⏱ 5 min · the 3 ingredients

Every correct recursive function has exactly these three ingredients. Click each one to see where it lives in the code.

static int factorial(int n) {
    if (n <= 1) return 1;                 // base case
    return n * factorial(n - 1);  // recursive case
}
Pick an ingredient above.

The same function, as plain Java


  
Forget the base case → the function calls itself forever → Stack Overflow 💥. Forget progress (e.g. calling factorial(n) instead of factorial(n-1)) → same disaster.







  
3. The Call Stack — watch it happen
⏱ 10 min · most important lesson
  
When a function calls itself, the computer stacks a new frame on top of the call stack (like stacking plates). A frame can't finish until the frame above it returns. At the base case the stack stops growing, then unwinds, passing answers back down.

4. How to think recursively
⏱ 6 min · the "leap of faith"
  
Beginners try to trace every call in their head — it hurts. Experts use the leap of faith: assume the function already works for smaller inputs, and only figure out how to use that answer.

  

    
🧠 Example: sum of an array — build the solution step by step

    

      
Step 1 — Define it. sum(arr) returns the total of all numbers in arr.

      
Step 2 — Smallest case (base). An empty array has sum 0.

      
Step 3 — Leap of faith. Pretend sum(arr without first item) magically works. Call it rest.

      
Step 4 — Combine. sum(arr) = first + rest.

      
Step 5 — Check progress. The array gets 1 shorter each call, so it must reach empty. ✅

      

    

    

  

  
Recipe:
1️⃣ What's the smallest input? → base case.
2️⃣ How do I shrink the input by one step? → recursive call.
3️⃣ Given the answer for the smaller input, how do I build the answer for this one? → combine.

  
Order matters: code before vs. after the call


static void demo(int n) {
    if (n == 0) return;
    System.out.println("going down " + n);   // runs BEFORE the call  (on the way down)
    demo(n - 1);
    System.out.println("coming up " + n);    // runs AFTER the call   (on the way up)
}

  
Use the visualizer above with countdown to see "down" and "up" printing — demo(3) prints 3 2 1 going down and 1 2 3 coming up.







  
5. Tree recursion: Fibonacci
⏱ 10 min · multiple calls & memoization
  
When a function calls itself more than once, calls form a tree. fib(n) = fib(n-1) + fib(n-2). Notice how the same values are computed again and again.

6. Types of recursion
⏱ 6 min · vocabulary
  

    
TypeIdeaExample

    
LinearOne recursive call per invocationfactorial, sum of list

    
Binary / TreeTwo (or more) recursive callsFibonacci, tree traversal, subsets

    
TailThe recursive call is the last thing done (nothing left to do after it returns)factorial with accumulator, gcd

    
HeadRecursive call first, work afterprinting a list in reverse

    
Mutual / IndirectA calls B, B calls AisEven / isOdd

    
NestedThe argument of a call is itself a recursive callAckermann function

  

  

    

      Not tail recursive (multiplication happens after the call returns)

static int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}

    

    

      Tail recursive (call is the last action; result carried in acc)

static int fact(int n, int acc) {
    if (n <= 1) return acc;
    return fact(n - 1, n * acc);
}
// call it as: fact(5, 1)

    

  

  
Some languages (e.g. Scheme) optimise tail calls so the stack doesn't grow. Java does not — the JVM never eliminates tail calls, so even a tail-recursive method can throw StackOverflowError on deep input. Use a loop when depth could be very large.

  
Mutual recursion


static boolean isEven(int n) { return n == 0 ? true  : isOdd(n - 1); }
static boolean isOdd(int n)  { return n == 0 ? false : isEven(n - 1); }







  
7. Classic problem: Tower of Hanoi
⏱ 10 min · play it, then see the recursion
  
Move all disks from peg A to peg C. Rules: move one disk at a time, and never put a bigger disk on a smaller one. Click a peg to pick up its top disk, click another peg to drop it.

  

    

      
      
      
    

    

    

    
Recursive log appears here during auto-solve…

  

  
The recursive insight: to move n disks from A to C:
1. Move n-1 disks A → B (using C) — leap of faith!
2. Move the biggest disk A → C.
3. Move n-1 disks B → C (using A).
Base case: 0 disks → do nothing. Minimum moves = 2ⁿ − 1.

  







  
8. Backtracking: generating subsets
⏱ 8 min · "choose / don't choose"
  
Recursion shines when you must explore many possibilities. For each item you make a choice — skip it or take it — and recurse on the rest. When you run out of items, you've built one complete answer.

  

  
👉 Open the visualizer in Lesson 3, select subsets, input abc and step through. Watch the Output printed box fill up with all 8 subsets.

  

    
🎛 Quick explorer: how many subsets?

    

    

  

  
Backtracking = recursion + undoing a choice after exploring it (e.g. remove the last item from the path). It's the engine behind N-Queens, Sudoku solvers, maze solving, and permutations.

10. Common mistakes & recursion vs. loops
⏱ 6 min · avoid the traps
  

    
❌ Missing base case
static int sum(int n) { return n + sum(n - 1); }
Fix: if (n == 0) return 0;

    
❌ No progress
static int f(int n) {
    if (n == 0) return 0;
    return f(n);   // same n!
}
Fix: call f(n - 1).

    
❌ Base case never reached
static void countdown(int n) {
    if (n == 0) return;
    countdown(n - 2);  // skips 0 for odd n
}
Fix: use n <= 0.

    
❌ Repeated work
Naive Fibonacci recomputes the same values exponentially. Fix: memoization / dynamic programming.

  

  
Recursion vs. iteration

  

    
RecursionLoop

    
Best forTrees, graphs, divide & conquer, backtrackingSimple repetition over a range

    
MemoryUses call stack (risk of overflow)Constant extra memory

    
ReadabilityElegant for self-similar problemsElegant for linear problems

  

  
Rule of thumb: if the data/problem is naturally nested or branching → recursion. If it's a flat sequence → loop.

13. Cheat sheet
⏱ revise before interviews
  

    
✅ Checklist
• Base case(s) written first?
• Recursive call moves toward base?
• Return value used correctly?
• Depth OK for max input?

    
🧩 Template
solve(problem):
  if tiny: return answer
  rest = solve(smaller)
  return combine(rest)

    
🚨 Red flags
• Overlapping subproblems → memoize
• Very deep input → iterate or use explicit stack
• Need all paths → backtracking
